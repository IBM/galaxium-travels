Issue #43 · tier-3 · enhancement

Refund Preview on Cancel

Show "$X refund / $Y fee / $Z kept as credit" breakdown before confirming cancellation

Estimate: ~1 hour Labels: area/frontend, enhancement, roadmap Out of scope: actual refund processing (payment stub)

1 · Cancellation Policy Design

The policy helper is pure logic — no I/O — keyed off days-to-departure calculated from the booking's associated flight departure_time. Three tiers cover all realistic cases.

Days to departureRefund %Fee %Travel credit %Wording
> 30 days90%10%0%Full refund less cancellation fee
8–30 days50%20%30%Partial refund; remainder as travel credit
0–7 days0%25%75%No refund; fare kept as travel credit less fee
Past / already departed0%100%0%Non-refundable — flight has departed
Note: Policy wording must be stored with the preview response — the frontend renders it verbatim, no business logic in the UI.

2
backend Add get_cancellation_preview() service function — services/booking.py
Add a new function below cancel_booking(). It:
  • Looks up the booking and its associated flight
  • Returns ErrorResponse if booking not found or already cancelled
  • Computes days_to_departure from flight.departure_time vs datetime.now(utc)
  • Selects the policy tier and computes integer amounts from booking.price_paid
  • Returns a CancellationPreview — no writes to the DB
This is a pure read — no seat or booking mutation happens here.
3
backend Add REST endpoint + import — server.py
Add the import for CancellationPreview to the from schemas import … block, then add the endpoint between the existing /bookings/{user_id} and /cancel/{booking_id} endpoints: 
@app.get("/bookings/{booking_id}/cancellation-preview",
         response_model=CancellationPreview, tags=["Bookings"])
def get_cancellation_preview_endpoint(booking_id: int,
                                      db: Session = Depends(get_db)):
    """Return refund/fee/credit breakdown without cancelling the booking."""
    result = booking.get_cancellation_preview(db, booking_id)
    if isinstance(result, ErrorResponse):
        status = 404 if result.error_code == "BOOKING_NOT_FOUND" else 409
        raise HTTPException(status_code=status, detail=result.model_dump())
    return result
FastApiMCP auto-picks this up — no manual MCP tool registration needed (mcp = FastApiMCP(app) is already present and wraps all routes).
4
test Unit-test the policy helper — tests/test_services.py
Add a TestCancellationPreview class with four test cases — one per policy tier. Each test seeds one User, one Flight, and one Booking, then calls booking.get_cancellation_preview(db, booking_id) and asserts on:
  • refund_amount + cancellation_fee + travel_credit == price_paid
  • Correct integer amounts per tier
  • policy_wording is a non-empty string
  • Error path: not found returns ErrorResponse with error_code == "BOOKING_NOT_FOUND"
  • Error path: already-cancelled booking returns ErrorResponse with error_code == "ALREADY_CANCELLED"
Uses the existing db_session fixture from conftest.py — no new fixtures needed.

6 · Project Footguns to Watch

RiskMitigation
GET /bookings/{booking_id}/cancellation-preview conflicts with GET /bookings/{user_id} route ordering FastAPI resolves static path segments before dynamic ones — place the new endpoint before the catch-all /bookings/{user_id} handler in server.py, or use a distinct path segment (/cancellation-preview is a string so FastAPI will prefer it over a bare int param). Confirm with a quick test.
Departure time stored as a string "YYYY-MM-DD HH:MM", not a datetime column Parse with datetime.strptime(flight.departure_time, "%Y-%m-%d %H:%M") before computing days_to_departure. Use timezone.utc consistently to match cancel_booking().
Frontend must inspect success: false / error, not HTTP status Use the existing isErrorResponse() helper from api.ts when handling the preview response — same pattern as cancelBooking().
Currency display — price_paid is an integer (credits, not dollars) Use the same formatting already in use on BookingCard / flight list pages for consistency.
