1 What Is This?

Galaxium Travels is a demo app for booking interplanetary space travel. Its purpose is to showcase challenges agents and developers face in a polyglot, enterprise-style codebase. Passengers can search flights, reserve seats on a time-limited hold, and confirm bookings across three services that communicate over HTTP.

The system supports 7 destinations: Earth, Mars, Moon, Venus, Jupiter, Europa, and Pluto — each with lore, hazards, and travel times ranging from 3 hours (Moon) to 36 hours (Pluto).

Key capabilities: Flight search with seat-class filtering · Quote → Hold → Confirm booking flow · Three independent seat classes (Economy, Business, Galaxium) · Dual REST + MCP API for browser and AI agent access · Auto-expiring holds · Full booking lifecycle (book, view, cancel)

Full booking-via-hold request flow

1Browser sends POST /quotes to Python, which proxies to Java — a quote is created with a 15-min timer (Q-2099-000001)
2Browser sends POST /quotes/{id}/holds to Python proxy → Java creates a hold (H-2099-000001, status HELD). Seat is not decremented yet.
3Browser sends POST /holds/{id}/confirm to Python proxy → Java calls Python /internal/bookings/from-hold
4Python creates the real Booking record in its DB and decrements the seat counter
5Hold status becomes CONFIRMED with externalBookingReference = booking_id

3 Travel Domain Concepts

ConceptWhat it means
QuoteA temporary pricing snapshot for a flight + seat class. Created by the Java service. Format: Q-2099-000001. Status is always CREATED.
HoldA time-limited seat reservation (15 min by default). The seat is not permanently removed until the hold is confirmed. Format: H-2099-000001.
BookingA committed purchase stored in the Python DB. Only created when a hold is confirmed. Statuses: booked, cancelled, completed.
Seat classesThree independent classes per flight: economy (60% of seats, 1× price), business (30%, 2.5×), galaxium (10%, 5×). Sold-out economy does not block business.
Hold expiryJava's HoldExpirationScheduler runs every 60 s. Holds past reservedUntil become EXPIRED and the seat is freed.

Hold status lifecycle:

HELD → CONFIRMED (user confirmed in time)  |  EXPIRED (scheduler)  |  RELEASED (user released)  |  CONFIRMATION_FAILED (Python callback error)

State management

No Redux or NgRx. State lives in useState hooks and a single UserContext. The user object is persisted to localStorage.

🚨 Never trust HTTP status codes from the proxy The Python proxy swallows Java errors and returns HTTP 200 with an error body. Always inspect the response body. 
// BAD — Java 404 appears as HTTP 200 through the proxy
if (response.status !== 200) throw new Error();

// GOOD — always inspect the body
const result = await api.post('/quotes', data);
if ('error' in result.data) {
  toast.error(result.data.error);
  return;
}

5 Python Backend (FastAPI)

The backend is the hub: it owns users, flights, and bookings directly, and acts as a transparent proxy to the Java service for quotes and holds. It also auto-generates an MCP server from its REST routes via FastApiMCP.

Key files

FilePurpose
server.pyRoutes, Java proxy endpoints, MCP registration
models.pySQLAlchemy ORM: User, Flight, Booking
schemas.pyPydantic types + ErrorResponse
services/booking.pybook_flight() → BookingOut | ErrorResponse
db.pyengine, SessionLocal, get_db() dependency
seed.py10 users, 10 flights, 20 bookings on first start

Service functions return Union types, not exceptions

# booking.py
def book_flight(...) -> BookingOut | ErrorResponse:
    if user.name != name:          # intentional dual validation
        return ErrorResponse(
            error="Name mismatch",
            error_code="NAME_MISMATCH",
        )
    return BookingOut(...)

# server.py route checks result at call site
result = booking.book_flight(db, ...)
if isinstance(result, ErrorResponse):
    raise HTTPException(status_code=409, detail=result.model_dump())
return result
MCP route order matters FastApiMCP(app) is called at the very end of server.py. Routes defined below that call are not exposed as MCP tools. Always place new endpoints above it.

6 Java Hold Service (Spring Boot)

This service owns the quote and hold lifecycle. You don't need deep Java expertise here, but you need to understand its role in the cross-service flow.

Key classes

ClassPackageWhat it does
HoldServiceservice/createHold(), confirmHold(), releaseHold() — all @Transactional
QuoteServiceservice/createQuote(), getQuote()
HoldExpirationSchedulerscheduler/@Scheduled every 60 s — marks expired holds
PythonBackendClientclient/HTTP callback to Python /internal/bookings/from-hold

Lombok convention

All Java entities use @Data, @Builder, @RequiredArgsConstructor — there are no hand-written getters, setters, or constructors. Assume all fields are accessible via .getFieldName() / .setFieldName() even if you can't see them in the file.

Java version requirement Java 17 or 21 only. Lombok does not support Java 22+. Verify with java -version.

E2E_RUN_SLOW=1 ./run-native.sh    # includes 90-second auto-expiry test
Test isolation Backend tests patch get_db via dependency_overrides — they never touch booking.db. Don't call SessionLocal() directly in service code; always use Depends(get_db), or tests will leak into the real database.

10 Critical Footguns

These will cost you hours if you don't know them upfront.

1
Proxy returns HTTP 200 on Java errorsAlways check response.data.error, never rely on HTTP status alone.
2
Service functions return Union types, not exceptionsUse isinstance(result, ErrorResponse), not try/catch.
3
book_flight() validates both user_id AND nameName mismatch rejects the booking. Frontend must pass the exact name from the user record.
4
FastApiMCP(app) must be the last call in server.pyNew routes placed below it are never exposed as MCP tools.
5
SEED_DEMO_DATA=true re-seeds on every start (if DB empty)Set to false to preserve local data across restarts.
6
Java requires version 17 or 21 onlyLombok doesn't support Java 22+. Verify: java -version.
7
Custom Tailwind colors only — no standard namesUse space-dark, cosmic-purple, etc. Not bg-blue-500.
8
Seat classes are fully independentSold-out economy does not block business or galaxium bookings.
9
Hold confirmation is idempotentRe-confirming the same hold returns the same booking — safe to retry, no double charge.
10
Never edit generated directoriesbooking_system_inventory_hold_service/target/ and booking_system_frontend/dist/ are build output. Regenerate, don't edit.

11 Suggested First Steps

  1. Run ./start.sh and open all three service URLs listed in Section 8.
  2. Create a user, search for a Mars flight, and go through the full quote → hold → confirm flow in the browser.
  3. Open Swagger UI at /docs and try GET /flights and POST /book directly.
  4. Read AGENTS.md at the repo root, especially the Footguns section.
  5. Run pytest booking_system_backend/ -v — read conftest.py to understand how DB isolation works.
  6. Trace one confirm request end-to-end: follow POST /holds/{id}/confirm from server.py → Java HoldController → HoldService.confirmHold() → PythonBackendClient → Python /internal/bookings/from-hold.
