3. How the app boots (equivalent to Angular's bootstrap)

The startup chain is short:

index.html (#root) → main.tsx — createRoot() → App.tsx — BrowserRouter + UserProvider + Layout → Routes → Page component

App.tsx is the entire "AppModule". It sets up three things in one go: the router, the global user context, and the persistent shell layout.

5. State management — no NgRx, just Context + useState

There is no Redux or Zustand. State lives in two places:

5a. Global user state — UserContext

UserProvider (in src/hooks/useUser.tsx) wraps the whole app. It holds the logged-in User object, persists it to localStorage under the key galaxium_user, and exposes setUser / logout.

Consume it anywhere with the useUser() hook — equivalent to injecting a singleton Angular service:

const { user, setUser, logout } = useUser();

Calling useUser() outside of UserProvider throws — the same pattern as an Angular service injected without its provider.

5b. Page-local state — useState + useEffect

Each page manages its own loading state, data arrays, and modal visibility with useState. Data fetching is triggered by useEffect. Example from Flights.tsx:

const [flights, setFlights] = useState<Flight[]>([]);
const [filters, setFilters] = useState<FlightFiltersType>({});

// Re-runs whenever `filters` changes — equivalent to ngOnChanges
useEffect(() => {
  loadFlights();
}, [loadFlights]); // loadFlights is memoised with useCallback([filters])

The useCallback around loadFlights prevents an infinite re-render loop — it memoises the function so the useEffect dependency only changes when filters actually changes.

6. API layer — src/services/api.ts

A single Axios instance with the base URL defaulting to /api (proxied to http://localhost:8001 by Vite in development). In production, Nginx handles the proxy — see nginx.conf.

⚠ Critical: HTTP status is not a reliable error indicator The Python backend proxy returns {"error": "..."} with HTTP 200 when the Java inventory service is unavailable. Always check the response body, not just the status code. The helper assertNotProxyError(data) does this for hold-related calls, and isErrorResponse(result) does it for booking calls.

The two error-checking patterns used in the codebase:

// Pattern 1 — union return type (booking/user endpoints)
const result = await bookFlight(data);
if (isErrorResponse(result)) {
  toast.error(result.error);
  return;
}
// result is Booking here

// Pattern 2 — thrown error (hold endpoints)
// assertNotProxyError() throws if data has an "error" field
// so you can use try/catch directly
try {
  const quote = await createQuote(payload);
  // quote is Quote here
} catch (err) {
  toast.error('Something went wrong');
}

7. The booking flow — BookingModal.tsx

This is the most complex component in the frontend. It is a 3-step modal with internal state that drives UI transitions — no separate routes.

Step 1: select → Step 2: quote → Step 3: hold
StepWhat the user seesAPI call(s)Side effect
select Seat class picker (Economy / Business / Galaxium), passenger info — Sets selectedClass
quote Price breakdown from the inventory service — Quote ID, per-seat price, total createQuote() → Java service Sets quote state
hold Countdown timer (15 min), Confirm / Release buttons createHold(quoteId), then either confirmHold(holdId) or releaseHold(holdId) storeHold() writes to localStorage; removeHold() cleans up on confirm/release
ℹ Hold persistence in localStorage When the user places a hold and closes the modal without confirming, the hold is intentionally kept alive. It is stored in localStorage under galaxium_holds_{userId} and surfaces in My Bookings as a "Pending Hold" card. The holdStorage.ts utilities manage this.

9. Animations — Framer Motion

Angular has built-in @angular/animations. Here the equivalent is Framer Motion. The pattern you will see everywhere:

<motion.div
  initial={{ opacity: 0, y: 20 }}
  animate={{ opacity: 1, y: 0 }}
  transition={{ duration: 0.3 }}
>
  ...
</motion.div>

whileInView + viewport={{ once: true }} is the equivalent of an Angular intersection-observer animation that fires once on scroll. whileHover replaces CSS hover transitions for interactive lift effects on cards.

10. Notifications — react-hot-toast

The Angular equivalent would be a snackbar service. Here it is react-hot-toast. The <Toaster /> is mounted once in Layout.tsx. Call from anywhere:

import toast from 'react-hot-toast';
toast.success('Booking confirmed!');
toast.error('Something went wrong');
toast.error('Failed to load flights. Retrying...');

11. User "auth" — no JWT, just name + email

This app uses a simplified identification model — there is no password, JWT, or session token. The user provides their name and email, and the backend looks up or creates a User record. The returned { user_id, name, email } object is stored in localStorage and held in React context.

The Header shows a Login button when no user is in context, and a user name + logout button when one is present. The My Bookings nav link only appears when a user is logged in. If you navigate to /bookings without a user, useEffect calls navigate('/flights').

12. Running the frontend locally

cd booking_system_frontend
npm install
npm run dev        # starts Vite dev server on :5173

npm run build      # TypeScript typecheck + Vite production build → dist/
npm run lint       # ESLint check

The Vite dev server proxies all requests to /api/* to http://localhost:8001 (the Python backend). You need the Python backend running for any API calls to work. You do not need the Java service unless you are testing the quote/hold flow.

You need running for…

  • Basic browsing: nothing (Home, DestinationDetail are static)
  • Flights list, booking, cancel: Python backend (:8001)
  • Quote & Hold flow: Python + Java (:8001 + :8080)

Key npm scripts

  • npm run dev — hot-reload dev server
  • npm run build — production build
  • npm run lint — ESLint
  • npm run preview — preview the dist/ build locally

13. Things that will surprise you

🚨 HTTP status ≠ success for holds The proxy returns 200 OK with {"error": "…"} when the Java service is down. Always call assertNotProxyError(data) or check isErrorResponse(result) after every API call.
⚠ React 19 StrictMode double-invokes effects in development StrictMode in main.tsx mounts, unmounts, then remounts every component in dev to surface side-effect bugs. If you see API calls firing twice in the browser DevTools — that is intentional in dev and does not happen in production.
ℹ useCallback and the loadFlights dependency loop loadFlights in Flights.tsx is wrapped in useCallback([filters]). This is necessary because it is listed as a dependency of useEffect. Without the memoisation the effect would re-run on every render, triggering an infinite loop. This is a common React pattern with no direct Angular equivalent.
ℹ No global loading/error state Unlike Angular apps that often use an HTTP interceptor for global loading spinners, each page manages its own isLoading state locally. There is no shared loading service.
